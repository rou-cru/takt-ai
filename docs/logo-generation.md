# TUI Logo Generation

The checked-in TUI logo is generated data, not a runtime image conversion. Regenerate all artifacts with:

```bash
go generate ./takt/tui/styles
```

The canonical source is the versioned `docs/assets/brand/takt-ai.png`. To use another PNG, run the generator directly:

```bash
go run ./cmd/generate-logo -input /path/to/logo.png \
  -output takt/tui/styles/logo_generated.go \
  -blocks-output takt/tui/styles/logo_blocks_generated.go
```

Generation requires **Chafa 1.18.2**, installed on the maintainer machine (for example, `brew install chafa`). Chafa is deliberately not included in the released binary.

The generator removes border-connected padding — near-white or near-black pixels — so the artwork blends with the terminal canvas, then produces two Chafa datasets from the same source:

- **Braille, foreground-only** — the mono-mode mark. Its shape survives the loss of color when `NO_COLOR` or a dumb terminal strips styling.
- **Half-blocks with foreground and background truecolor** — the color-mode mark. Every cell carries two colors, so the logo tracks the original artwork much closer than the Braille line art.

and parses them into two checked-in artifacts:

- `takt/tui/styles/logo_generated.go` — the Braille dataset, consumed by `styles.RenderLogo` in mono mode.
- `takt/tui/styles/logo_blocks_generated.go` — the half-block dataset, consumed by `styles.RenderLogo` in color mode.

OpenCode carries no generated logo. Its V2 terminal publishes no home-screen
logo slot, so `takt/agents/opencode/assets/takt-logo.tsx` is a hand-maintained
plugin that renders the compact brand mark in the home footer's status row.

The shared `logoSpan` type lives in `takt/tui/styles/logo.go`; generated files carry only data. Both carry the `Code generated by cmd/generate-logo; DO NOT EDIT` header and must only change through the generator.
