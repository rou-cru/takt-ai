# Memory Implementation Plan: Independent MCP Memory Service — Part 1 of 3: scope, evidence, architecture

## 1. Purpose and reader's guide

This plan is the complete implementation proposal for replacing the memory functionality Takt exposes through Engram with an independent MCP memory service. It carries the architecture, the closed contracts, the work packages, the execution sequence, the acceptance basis, the deferred scope, and the evidence behind every claim. It is self-contained: a reader implements from this document alone.

How to read it. Section 2 states the binding constraints every later section obeys. Section 3 lists the evidence consumed, the state of the reviewed corrections, and the limits that remain unverified. Section 4 is the architecture: boundaries, interfaces, references, retrieval, identity, adapter, lifecycle protocol, semantic seams, and the decision record. Part 2 (section 5) is the work-package registry, the parity ledger, RD-1, and deferred work. Part 3 (section 6) is the orchestrator-approved H0-H6 execution sequence, section 7 is the acceptance and certification basis, and section 8 lists the sources.

Status. The design recorded here is reviewed and approved as implementation intent. Every module, API, command, and test marked proposed or F does not exist yet. Nothing has been run, built, installed, or tested against it. Runtime, security, and performance behavior stays unverified until the section 7 evidence is produced. This document executes nothing by itself.

## 2. Binding constraints and scope boundaries

- Breaking change from Engram. Fresh data only: no historical import, no migration, no fork, no aliases, no dual write, no second database backend. Existing user data stays intact and untouched.
- The first cut delivers every memory function Takt currently exposes, efficient lexical retrieval without Dream, and the semantic foundations. The semantic runtime and Dream are later, separate work.
- Routing is operation-specific. Crew to MCP, crew to harness to MCP, and harness to MCP are all valid; the operation, the acting identity, the available knowledge, and the necessary controls determine the route. Deployment topology does not determine routing. No universal broker, no mandatory global proxy, and no service-owned crew narrator exist.
- Crew runtime identity, interactive control, delegation, deterministic confirmation, and crew lifecycle admission stay with the harness. The service decides only data-dependent source and session preconditions.
- The service runs as a local process of the existing takt-ai binary (section 4.1). That packaging choice is plan detail; no product requirement obliges the installer to execute the service.
- The product requirements this plan implements live in product/meta-harness/context/PRD_MEMORY_SERVICE.md (new) and in the updates to product/INDEX.md, product/GLOSSARY.md, product/meta-harness/context/ARCH_MEMORY.md, product/meta-harness/harness/PRD_HARNESS.md, product/meta-harness/platforms/PRD_PLATFORMS.md, product/app/PRD_SETUP.md, and product/app/installation/PRD_INSTALLATION.md.

## 4. Architecture

### 4.1 Boundaries, reuse and packaging

The C4 container model has agent and manual clients, the independent memory executable, its private SQLite database, and optional external identity infrastructure. Inside memory, a single application owns admission, immutable source, relations, memory-session graphs, receipts, and bounded queries. MCP is an adapter. The harness owns crew runtime identity, interactive control, delegation, deterministic confirmation, and crew lifecycle admission. Memory never reads VFS locks, crew catalog files, or execution-history files.

Reuse the repository's Go release infrastructure, database/sql, and pinned modernc SQLite. FTS5 and libc alignment have source evidence in #15778, not four-platform execution proof. Proposed module boundaries are takt/memory/domain for shared types and rules, application for operations, sqlite for concrete storage, mcp for SDK adapters, and client for typed access. The existing takt/memory crew-specific admission becomes a harness integration module, not a dependency of the service. Choose the existing takt-ai executable, launched as an independent process with the new public subcommand takt-ai memory serve, to compose these modules. The same binary provides memory client and memory admin command groups; the old internal memory-command dispatch is replaced within this breaking change. .goreleaser.yaml:11-27 already builds ./takt/cli as takt-ai with CGO_ENABLED=0 for Linux and macOS amd64 and arm64; existing archives, checksums, signing, and package channels distribute it. No second binary, installer, or signing chain is justified for first parity. The service command does not initialize crew history, OpenCode, or setup state. Code linkage with the installer costs binary size, not runtime dependence; a separately distributed binary remains unnecessary until a demonstrated distribution need. Cohesive files remain below 1000 lines.

Remove Engram endpoint and startup coupling from takt/memory/client.go and the second memory-session index in session_index.go. Canonical session membership moves into the service transaction. Reuse history and dispatch as execution owners; extend their existing serialized admission rather than introduce another crew controller. Catalog and setup remain instruction and deployment owners. Doctor consumes memory diagnostics rather than opening its database remotely. Crew-specific matrix-column and role rules stay in crew admission, not universal public memory rules.

Run one independently running local service because multiple clients need the same corpus without OpenCode. It exposes authenticated loopback Streamable HTTP. An optional stdio forwarder connects to that owner; it never opens SQLite or creates another corpus. Local lifecycle explicitly selects or starts the owner and checks readiness. Unavailability never silently creates an empty replacement.

For the later central deployment, crew Deployments and external clients call an internal MCP Service backed by one active memory StatefulSet replica and private attached block storage. Clients never mount SQLite. WAL is not a multi-host shared-file protocol [S2]. A StatefulSet supplies neither replicated writes nor HA. Replacement requires exclusive attachment, old-owner fencing, recovery, and readiness. Cluster manifests, identity adapters, and storage and failover validation are not initial implementation. This deployment supports remote clients without forcing every crew operation through a particular intermediary.

### 4.2 Versioned interfaces for parallel consumers

Use the official Go MCP SDK's typed AddTool, StdioTransport, and NewStreamableHTTPHandler [S1]. Prefer stateless HTTP transport; durable domain sessions do not depend on MCP transport sessions. SDK, protocol, and host compatibility needs a pinned release matrix. MCP version negotiation does not negotiate memory semantics.

Define domain API v1 schemas once in domain. MCP tool input and output schemas and resources derive from those types. Database source-schema and derived-schema versions are separate. Unknown API majors or newer source schemas refuse incompatible operations; additive optional fields retain existing meanings. There are no Engram aliases.

Shared shapes are:

- Ref = {memory_id, entry_id}, both opaque strings. memory_id identifies a tenant-owned workspace or global corpus. Neither ID is a capability.
- ReadOptions = {max_bytes?, limit?, cursor?}. Defaults are 16 KiB and 20 items; hard maxima are 64 KiB and 50 items. Batch exact reads accept at most 32 references. These are proposed contract limits, not measured SLA figures.
- ReadPage<T> = {api_version, snapshot_seq, observed_seq, incarnation, items:T[], bytes_used, truncated, next_cursor?}.
- MutationContext = {operation_key, expected_session_revision?, confirmation_ref?, admission_ref?}. Authentication and trusted attribution arrive through transport context, never authored content.
- MutationReceipt = {operation_key, disposition:applied|rejected|canceled, payload_digest, commit_seq?, result_refs?, session_revision?, error?}. This is a terminal union: applied requires commit_seq and its operation-specific result; rejected requires DomainError and no committed source effects; canceled has no source effects. OperationResult is this terminal receipt, never pending.
- OperationStatus = {state:pending, operation_key, payload_digest} | {state:terminal, receipt:MutationReceipt}. Status queries return this separate tagged union. Pending means registered without a terminal receipt; it claims no progress or write completion. An unknown key returns not_found, not canceled and not proof that a delayed submission cannot arrive.
- DomainError = {code, message, retryable, continuation?}. Codes are invalid_argument, forbidden, not_found, conflict, stale_precondition, cursor_expired, busy, overloaded, and unavailable. Cross-tenant denial reveals no object existence.

The finite public MCP operations are:

| Tool | Consumed request and returned result |
| --- | --- |
| memory_info | Optional authorized corpus and view readiness, diagnostics, and review; returns versions, limits, capabilities, or bounded diagnostic and review results. |
| memory_current_workspace | Explicit workspace reference or client-local directory hint; returns registered identity, detection source, and authorized alternatives. No creation on read. |
| memory_search | query, project or personal scope, optional type, limit, include_history, all_workspaces, authorized workspace selection, and ReadOptions; returns compact hits, conflict and exception flags, and omitted-superseded accounting. |
| memory_get | Tagged EntrySelection or SessionSelection, view metadata, content, status, history, session_index, content selector or history_cursor as allowed below, plus ReadOptions; returns exact details or per-item outcomes. |
| memory_context | Authorized selection, compact, older_history, max_bytes, and cursor; returns bounded orientation and history, never automatic session dumps. |
| memory_record | title, content, nature, scope, evidence?, relation?, user_order intent, and MutationContext; returns committed Ref, digest, and operation result. |
| memory_continue_session | Bound session, previous closed-session reference or empty withdrawal, and MutationContext; returns revised declaration or result. |
| memory_close_session | Bound session, objective and state for explicit closure or authorized fallback mode, and MutationContext; returns end-anchor Ref and entry count or result. |
| memory_operation | operation_key and action status or cancel; status returns OperationStatus, cancel returns MutationReceipt. Cancellation is separately authorized. |

memory_get validates a discriminated request, not a permissive bag of selectors. EntrySelection is {kind:entries, refs:Ref[]} and permits metadata, status, content, or history. SessionSelection is {kind:session, session_id, author_id?, caller_id?} and permits only session_index. Exactly one selection is required. A content view accepts either a section_id or {offset_bytes,length_bytes}, never both; these fields are forbidden on other views. Byte ranges outside the source or inside a UTF-8 code point reject. History alone accepts history_cursor, an alias for its continuation cursor; supplying both cursor forms rejects. include_history remains available for entry detail: it adds bounded evolution references, not inline successor bodies; history view requires it absent or true. Other cross-view combinations reject invalid_argument. Shared JSON schemas encode these alternatives with closed tagged unions.

Generic memory-session creation is an authenticated binding operation in the client admission adapter, not a knowledge-writing tool. Tools use that bound session. Read status and evolution remain distinct from nature. An old Ref never silently resolves to a successor. Search ordering is deterministic by score then committed position or ID; chronology and authorial order remain available in session and history views.

Go application handlers expose Execute(ctx, Principal, Command) (OperationResult, error) and Query(ctx, Principal, Query) (ReadPage, error). Tagged commands and queries are the closed schemas above. The SQLite owner supplies their transactions, not caller-provided transaction callbacks. Domain errors are typed tool failures; malformed JSON-RPC is a protocol error. No network call or inference occurs inside a database write transaction.

Issuer control also uses standard MCP, not an undefined RPC. On the authenticated /mcp Streamable HTTP listener, the three protected tools memory_issuer_register_identity, memory_issuer_bind_session, and memory_issuer_register_command implement RegisterIdentity, BindSession, and RegisterCommand. Only enrolled issuer principals discover them, and every handler independently checks issuer authentication, current registration, namespace, and permission ceiling. Hidden discovery alone is not authorization. RegisterCommand binds issuer, operation key, payload digest, actor, session, corpus, and permitted operation, returning an opaque admission_ref. Generic session binding is the permitted fixed-author branch of memory_issuer_bind_session: it is exposed to enrolled fixed-author clients solely for their own identity and session, never crew namespaces or assertions. The ordinary nine knowledge and read tools remain the finite agent-facing set; issuer tools are never projected to crew agents.

Administration is a distinct protected MCP connection over the operator Unix socket. The memory admin CLI uses HTTP over that Unix socket with the SDK's same Streamable HTTP /mcp handler and normal initialize, tools/list, and tools/call messages; its owned HTTP dialer selects the socket instead of TCP. Filesystem ownership and modes establish the local operator principal. Only that listener exposes memory_admin, whose tagged actions are enroll_principal, enroll_issuer, rotate_credential, revoke, and confirm_intent. These actions retain the bounded enrollment, ceiling, and digest-bound confirmation contracts here; none is arbitrary SQL or a content-deletion command. The network listener cannot advertise or invoke memory_admin, even with an issuer credential. Issuer and administrative tools call the same domain application and SQLite owner. This keeps all client data and control messages on defined MCP semantics without creating a second business API. Unix dialing and SDK integration remain execution-unverified.

### 4.3 Reference integration and invariant ownership

Domain owns Ref plus EncodeInvariantRef(Ref) (string,error) and DecodeInvariantRef(string) (Ref,error). The exact invariant token is memory:v1:<M>:<E>, where M and E are unpadded base64url encodings of the UTF-8 memory_id and entry_id. Both decoded IDs are nonempty service-issued opaque values; padded, noncanonical, extra-segment, or invalid-UTF-8 forms reject. Encoding and decoding are defined once in takt/memory/domain, without a dependency on VFS or runtime state. Ordinary MCP payloads retain the Ref object; the token is its canonical representation in mixed file and memory invariant lists and readable citations.

The owned crew integration surface replaces EngramInvariant and engramInvariantPrefix in takt/vfs/verdict.go:36-55, caller.go:74's extraction and denial text, and takt-vfs.ts:318's numeric citation rendering. VFS keeps its mixed InvariantSet list but recognizes only the reserved memory:v1 token for memory inputs. Malformed memory-prefixed values fail rather than fall through to a filesystem path. It hashes the canonical token for immutable entry pins; file invariants retain content hashing. Crew admission resolves authorized existence and author and session requirements through memory before binding. VFS does not open the DB or turn this immutable identity pin into a live-applicability cache.

The memory domain owner supplies the codec and schema; the crew-memory integration owner supplies VFS bind, verdict, and caller adoption and dispatch and plugin rendering. For TPM, this is an explicit WP-ISS integration deliverable consuming the domain Ref contract, not an implementer inventory item. Dispatch input declarations, handoff result arrays, persisted execution references, catalog examples, and error continuations consume the same Ref and codec. Numeric IDs, engram:<int64>, and implicit single-corpus shortcuts are not accepted by the new format. Older runtime state is preserved and reported incompatible where necessary, never silently reinterpreted, migrated, or deleted. New corpus references need no historical import.

### 4.4 Retrieval identity, budgets and freshness

Refs remain stable through grouping, reindexing, client changes, and restoration of the same corpus. New corpora receive new identities. Restore changes incarnation and invalidates previous cursors. Source content has a digest; deterministic section indexing records parser version and UTF-8 byte spans. Entries without headings remain range-readable.

Define encoded-size accounting exactly at the owned output boundary. For MCP tools, count UTF-8 bytes of the compact JSON serialization of the complete CallToolResult, including content blocks, structuredContent, isError, and emitted metadata. This includes escaping and every duplicate text or structured copy, but excludes the JSON-RPC id and envelope, HTTP/SSE framing, compression, tokenizer overhead, and host-added instructions. bytes_used reports that total; compute its own digit contribution to a stable size before emission. Resource reads count the full compact resource-read result equivalently. No hidden full body accompanies a truncated view.

The Go MCP serializer and finalizer owns counting and bounded assembly, including bounded error output. Advertise a minimum response-envelope budget; impossible budgets reject. Prefer structured output with a minimal text pointer where supported; text fallback fits the same total. The first OpenCode wrapper emits only the selected bounded result, without added prose, raw upstream response, or duplicated body. Its adapter finalizer additionally measures its owned host-tool projection and requests a smaller page if that projection exceeds the requested budget. It never clips an already-generated artifact or cursor. Host-generated framing outside these owned projections is explicitly outside this byte contract; host-visible context and token size remains an acceptance measurement, not an asserted universal guarantee. Large artifacts return reconstructible ranges and digests. Batch order follows request order; aggregate bytes and counts remain bounded. Continuation identifies both the next request item and any partial content offset.

Opaque integrity-protected cursors bind principal, tenant, authorized corpus set, query, filter, order, API, snapshot sequence, incarnation, and expiry. Each page reauthorizes current access. Logical as-of predicates over append-only facts preserve paging without holding a WAL transaction across requests. Later changes appear in observed_seq, not mixed into the page. Invalid history_cursor and query combinations reject.

Indexes support exact partitioned keys, committed chronology, session, author, and caller membership, and incoming and outgoing evolution edges. FTS5 updates with source writes. Canonical scope and status predicates precede result limits and body retrieval. Applicability derives from canonical relations, not a competing cached active flag. Frequent-read caches store immutable bodies by Ref and digest; live authorization and status always read their owners. Search caches require matching source sequence and authorization scope or are bypassed. MEM-RET-6 sublinear status-aware retrieval requires actual query plans and corpus-growth measurements; bounded output alone proves neither complexity nor speed.

Optional bounded resource templates for exact metadata and sections invoke these same queries and schemas. Tools remain sufficient on hosts without resource support. No resource catalog enumerates the corpus.

### 4.5 Identity, isolation and manual clients

The first local trust root is the OS account owning a private service directory. Recommend mode-0700 directory and mode-0600 operator Unix socket. The operator CLI enrolls the initial personal tenant, human principal, and individual clients through that socket. Only the service opens the DB. No unauthenticated HTTP enrollment or agent-facing admin tool exists. Same-UID processes share this trust boundary; modes do not isolate hostile same-user programs.

Issue independent opaque random bearer credentials using standard library mechanisms and store only verifiers. Credentials bind service and principal, are presented in headers, and are checked on every request. Rotation and revocation are service-owned. No JWT issuer, custom cryptographic protocol, or bespoke identity provider is introduced. Loopback is not authentication; local HTTP is an OS-bound profile, never an externally bound plaintext fallback. Remote hosting requires TLS and maintained integration with an existing OAuth/OIDC authority, resource-audience validation, and MCP authorization requirements [S3]. Provider choice and client OAuth interoperability remain unverified.

A human client has its registered human author. An independent automation client has a fixed integration author and service-bound generic sessions. Neither inherits crew privileges. A registered issuer may assert author instances and host, root, and caller labels only within its enrolled namespace, corpus set, and operation ceiling. The service assigns canonical identities and records issuer provenance. An agent cannot turn MCP clientInfo, transport session IDs, or author arguments into trusted identity.

The local operator enrolls issuers explicitly. Takt's runtime identity adapter is one issuer, not the universal route. Crew direct MCP calls can carry adapter-injected scoped identity and admission handles; harness calls carry the appropriate initiating author and separately recorded executor. A harness-executed fallback is attributed as fallback, not falsely as holder-authored content. Issuer credentials stay in trusted processes, outside model inputs and callable tool arguments. Manual clients receive separate secrets through protected input or credential stores. No credential enters memory, URLs, or logs. Generic fixed-author HTTP clients are supported design targets; reference manual and Takt adapters require execution validation. Other-host delegated attribution, resource UX, and stdio compatibility remain unverified.

Service permissions and revocations govern corpus access and generic operations. They are not copies of crew-holder state. Parent issuer revocation disables descendant grants on admission. Required confirmation binds principal, action, scope, and exact payload digest. Crew capture uses deterministic harness confirmation under MEM-TYP-2; an enrolled harness supplies its attributable receipt. Independent human confirmation uses the protected operator channel. A model's user_order=true or evidence string cannot manufacture approval. Enrollment authority does not grant content-deletion rights.

Tenant is a hard partition. Global means organization-global within that tenant, or the personal user's single-user tenant, never service-global. Workspace names and remotes do not establish identity or membership. Clients explicitly register local location mappings; the remote service does not probe supplied paths. Cross-workspace access and continuity require authorization to both endpoints. No third tier or implicit cross-team sharing is added. Detectable project excerpts are rejected from global writes, but structural checks do not certify arbitrary text as non-proprietary.

### 4.6 First OpenCode adapter and role permission derivation

Choose the existing server-plugin tool-wrapper mechanism for the first OpenCode adapter, not an assumed hook that rewrites native MCP calls. takt-memory.ts:179-183 receives host-delivered agent and session context, :200-342 registers tool executors through ctx.tool.transform, and :186-197 subtracts lifecycle tools per turn. Its current Bun.spawn path calls the CLI; the new wrapper calls the owned memory invoke adapter, which uses the Go MCP client to call the independent service. Identity comes from execute(input,c), not model fields. The Go adapter resolves root and caller and runtime-dependent admission under the existing execution owner, obtains scoped handles with the protected MCP issuer tools, and injects those handles as reserved request metadata. Authentication headers are added by the trusted client. The server principal-binds all handles. Source schemas reject authored identity and session assertions outside the trusted context.

The canonical wrapper input schemas omit transport identity and operation machinery that the adapter generates; user content and options still map to the public v1 requests. No plugin-specific persistence or alternate memory semantics exist. Do not simultaneously expose unbound native write tools under another name that bypass this attribution. This is an intended OpenCode route based on an existing repository mechanism, not a universal routing requirement. A host capable of trusted per-call MCP identity injection may call MCP directly; such a native OpenCode injection hook is not established and is not required by the first design. The independent manual client and harness-initiated calls remain direct MCP clients.

Current official V2 plugin documentation confirms server tool transforms, execute context, context hooks, and executable snapshots [S4]. The repository provides source evidence for the specific attribution and confirmation adapter. New wrapper-to-Go-SDK-MCP composition, metadata delivery, installed host versions, and final output sizing remain unverified. No shared model-visible issuer secret is an acceptable substitute.

The canonical crew memory-policy derivation belongs to the existing crew admission owner refactored from takt/memory, consuming catalog role and instance identity. Its rule is: non-maintenance crew roles receive scoped read and append; ordinary lifecycle tools are projected only to orchestrator or HoldsInterface roles, then current author and caller eligibility is checked at execution. Every operation requires an authenticated valid principal and its scoped author: an unknown or unauthenticated identity authorizes no operation, including independent reads or recording. Unavailable holder authority for an established principal denies lifecycle only, not all independent reads or recording. This matches memory.Capabilities and renderer.go:266-274. Maintenance receives no ordinary append or lifecycle grant; only explicitly scoped cycle operations can be issued by the harness under the maintenance contracts. No model role receives issuer or admin tools. Global and user-prompted writes additionally require the defined confirmation, regardless of role.

Implement that rule once as MemoryCapabilities(identity) in crew admission. renderer.agentPermissionRules projects its static upper bound into OpenCode; the context hook only subtracts unavailable runtime actions. Registered issuer ceilings and service corpus grants bound those capabilities independently, never broaden them. Ordinary operation status is allowed for the caller's own keys; cancel is allowed only where the actor or issuer already has cancellation authority. Harness fallback, recovery, and confirmation execute under explicitly registered system capabilities, outside ordinary agent permissions. Existing unconditional maintenance projection is aligned to the owning MEM-AUT-1 restriction rather than treated as authority. This fixes the per-role owner and rule now without creating another policy store.

### 4.7 Crew lifecycle authority and completion protocol

Existing authority is preserved. MEM-OPS-4 says, exactly, "The interface holder contributes only the session objective and its final state" and "No other agent contributes a session narrative." MEM-OPS-5 says, "Continuity with a previous session exists only when the interface holder declares it." Neither specifies a new distributed commit-time test. STR-16 nevertheless requires the decision and authorized action to share serialization. Current takt/cli/memory.go:105-131 holds the workspace lock across the lifecycle call, and memory.go:748-858 checks runtime author and caller against history. The source supports preserving serialized holder authority, not inventing a new narrator or claiming MCP requires amendment.

Generic external sessions are not crew conversations. Their bound principal can append and close under service permissions. Crew sessions are registered under an enrolled crew issuer and cannot be closed or continued through generic-client permissions. Crew identity, holder eligibility, confirmation, and fallback authority are decided at the execution owner. Only data-dependent source and session preconditions are decided at memory.

A durable command reservation covers crew operations whose authority depends on mutable runtime facts, especially close and continue. Reuse execution history and its workspace serialization. A proposed AdmitMemory(actor, command) atomically reads current holder and caller facts and appends an operation reservation with unique key, exact digest, affected root, and actor. That commit is the lifecycle authorization linearization point. It reserves the relevant exclusion: holder transitions and termination or ownership release cannot invalidate that admitted action before completion. Ordinary reads and unrelated work do not acquire this reservation.

The executor registers the exact admitted command with memory and may submit it itself or let the authorized crew caller submit directly over MCP. Memory trusts only enrolled issuer registration, not a model's claimed history sequence. The admission_ref is principal-bound and payload-bound. It proves admission of one immutable action, not current holder status or broad future permission. There is no universal harness proxy and no memory-side holder mirror.

Memory serializes submit and cancel for the operation key. Submit validates current service access, admission binding, and expected memory-session revision, then commits source effects plus a terminal receipt together. That commit is the persistence linearization point. Cancel creates a terminal canceled tombstone even if submission has not arrived. If submit won, cancel returns applied; if cancel won, any delayed registration or submission cannot revive the key. Reject is also terminal. All reuse with a different digest fails. Receipts and tombstones survive restart and are retained for the entire lifetime of their service or corpus identity. There is no time-based garbage collection in initial parity. Retain the minimal operation key, issuer or principal binding, digest, terminal outcome, and result references, not a duplicate artifact body. Keys are never reused or reopened after rejection or cancellation. Administrative credential rotation, Dream, and source maintenance cannot delete this control evidence. Only explicitly authorized retirement of the corpus or service identity ends its lifetime, after pending crew reservations are reconciled; retired identities remain non-reusable. Storage-growth cost is accepted rather than inventing a finite retention interval that admits arbitrarily delayed replay.

After observing that terminal receipt, CompleteMemory(key, receipt) appends completion to execution history under its lock and releases the reservation. These proposed history events are control-plane state, not memory entries or another plan store. Every holder transition checks unresolved reservations in that same owner. A crashed caller therefore releases no authority by merely losing its OS lock. Recovery enumerates pending commands, queries or retries the same key or obtains cancellation fencing, then completes. A timeout is unknown outcome, never proof of non-commit. An outage can temporarily block the affected holder transition; resolution controls remain available without another specialist slot. Safety costs availability for that root. A TTL cannot release it.

This protocol has two commits, not a distributed transaction. Holder eligibility is read at admission and protected until the service outcome, so the admitted actor remains entitled through persistence. Source success can precede history completion; recovery closes that gap without duplicate writes. New execution owners for the same root require exclusive access to its canonical history and reconciliation; independent pod histories cannot jointly own it. Restore of either store requires quiescence and receipt and reservation reconciliation before admissions.

Ordinary record calls use direct scoped attribution when sufficient; runtime-dependent rules use the same admission mechanism. The harness may intervene or execute any appropriate operation. Closure races use expected_session_revision: a concurrent entry can make a close stale rather than silently omitted. Continuity remains replaceable or withdrawable before the first new entry; first entry fixes it transactionally. New writes can reopen a closed host conversation, preserving earlier anchors; retries do not. Explicit empty close records anchors. Current empty fallback no-op remains the identified MEM-RET-8 target gap.

Handoff validates committed result Refs, author, session, and caller membership, and bounded session indexes through memory, then executes the existing crew transition. Memory success is not undone by a failed handoff. Runtime plans and budgets remain solely in history. No narrator transfer or product amendment is required by this design.

### 4.8 Source transactions and semantic seams

Initial source schema owns immutable authored bytes and digests, attribution and authority and evidence, natures, corpora, append-only evolution, session anchors and membership, pending continuity, operation receipts, access grants, and committed change sequence. One transaction includes authorization and preconditions, source, relations, and session effects, FTS, and receipt. Content dedup is distinct from idempotency and never merges authors. Corrects and supersedes append complete artifacts; supplement adds a distinct artifact. Unresolved disputes and exceptions remain explicit, not resolved by recency.

Derived schema has separate versioning. Initial implementation needs lexical and section indexes and sequence-backed freshness, not empty model tables or a job bus. Semantic contracts are fixed now: managed manifests identify task, pinned model, runtime, and tokenizer artifacts and licenses, preprocessing and input fields, chunk spans, dimensions and labels, normalization and distance, and numeric encoding. Lifecycle administration admits manifests after owner validation; workers cannot register models. This retains #15778's manifest-admission correction.

Later bounded CPU workers receive exact Ref, digest, and input hashes and a fixed manifest without SQL or arbitrary-command access. Results carry ordered evidence and generation. The owner validates hashes, shape, and finite values. Private generation builds consume the committed change sequence; atomic publication names coverage through P, leaving later entries explicitly uncovered. Model changes create separate generations. Checkpoints are progress, not applicability. Vectors use manifest-defined encoding with a disposable validated acceleration index. Inference never holds the source write lock. Mandatory future write-time representations are computed outside the transaction and committed with source after precondition checks, not mislabeled asynchronous completeness.

Lossless compact views retain source identities, full constituent content, byte spans, attribution, evolution, and coverage. Summaries and classifier signals never replace source or authorize promotion or deletion. MEM-RET-7's embeddings and consolidation-only restriction remain later-target constraints, not permission to implement semantic retrieval now. Future Dream can colocate processing with memory and broker only authorized provider egress. PR-DRM-6, PR-DRM-16, and PR-DRM-20 still constrain internal network traffic, local scoring, harness scheduling and barriers, and typed-operation admission. Trusted-boundary and egress policy needs explicit resolution before Dream deployment; this is not a current MCP parity failure.

### 4.9 Operations, durability, and decision record

Single-owner SQLite uses WAL, foreign keys, durable synchronization, bounded pools and queues, and per-tenant fairness. Waits and deadlines end with busy or overloaded and same-key continuation. No inference or external call holds its transaction. Consistent backups include WAL state; corruption never triggers source reset. Unknown newer schemas refuse writes. PostgreSQL is justified only by measured write contention, required independent writers, availability beyond a fenced single owner, or unacceptable recovery and storage limits. No unused multibackend code is proposed.

Catalog and setup re-project shared memory rules, role guidance, examples, permissions, and bootstrap instructions together. Obsolete Takt-managed .takt-ai/bin/engram and owned MCP and plugin contributions receive scoped lifecycle accounting, with drift preservation and choice. PATH binaries, third-party plugins, and historical data remain untouched. Uninstall reports retained native data and honors explicit deletion controls.

Sequencing rules, as approved:

- H2, H3, and H4 can develop independently against the frozen H0 contracts. Their development does not wait on H1.
- Integrated acceptance waits on the actual H1 core: a milestone's end-to-end scenarios run only once the transactional core they exercise exists.
- Shared transaction-owner files are not parallel-writer shortcuts. Packages that meet in the same owner files (the application module for WP-ATH, WP-REC, WP-SES, and WP-OPS; the sqlite module for WP-STO and WP-IDX; the history and dispatch files for WP-ADM and WP-HND) are serialized per owner: one writer per owner file set at a time, the same rule the packages themselves rely on for decision reads and authorized actions.
- H0 freezes before dependent work starts: golden fixtures and the parity criteria are the reference every later milestone is judged against, and a change to a frozen contract is a new H0 revision, not an inline edit under downstream work.
- H6 is the only place full parity may be claimed, and only under close rule 1 of section 5.9.

## 7. Acceptance and certification

### 7.1 Bounded acceptance scenarios

The delivery is accepted on fresh data against these scenarios: manual and crew clients sharing one fresh corpus; same-named workspace and cross-tenant isolation; global confirmation; immutable evolution, status, and history; exact, batch, and section reconstruction within total bytes; cursor reauthorization and expiry; continuity, close, reopen, and handoff ownership. Startup and setup repetition converge, and scoped uninstall preserves unrelated assets.

### 7.2 Failure scenarios

Forged issuer namespace; changed idempotency payload; parent revocation; concurrent entry versus close; submit and cancel races; crash after either commit; delayed packets after cancellation; lost replies; disk-full; corrupt derived or source data; storage fencing failure. Each must end in the terminal disposition its contract defines, with no source effect beyond the committed one.

### 7.3 Measurements

Measure context bytes, lookup and scoped-search plans across corpus growth, status filtering before body access, cache freshness, queue and lock waits, fairness, overload, WAL growth, and backup, restore, and recovery cost. Workload, hardware, and acceptance thresholds are agreed with the orchestrator and user before measurement; results are reported against those thresholds or marked unmeasured. No benchmark figure in this plan is a fabricated target: the read limits in C1 are proposed contract limits, not measured SLA figures.

### 7.4 What cannot be claimed yet

All runtime, security, and performance acceptance remains unverified until H6 evidence exists. The actionable evidence blocker is review-due store scheduling semantics (RD-1), not upstream endpoint availability, MCP routing, or crew narrator policy. The design warnings W1-W3 are addressed by separate status and receipt schemas, an owned invariant Ref codec and integration, and explicit protected MCP control transports; S4-S6 are resolved as contracts (view validation, permanent receipt lifetime, precise encoded accounting), not as executed assurances. MEM-RET-6 sublinear retrieval, four-platform FTS5 capability, and every item in section 3.3 stay open until its named package produces evidence.
