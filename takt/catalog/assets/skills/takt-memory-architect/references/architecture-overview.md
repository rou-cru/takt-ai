# Architecture Overview

| Field | Holds |
| --- | --- |
| System purpose | What the area or system exists to do, and for whom |
| Boundaries | What is in scope versus out of scope, and where this system's responsibility ends and a neighbor's begins |
| Major components | The system's existing or decided top-level parts and what each one owns, never a task breakdown |
| Data flow | How data or control moves between the major components as built or decided, never a migration plan |
| Key constraints | The non-negotiable technical, operational, or business limits that shaped these decisions |
