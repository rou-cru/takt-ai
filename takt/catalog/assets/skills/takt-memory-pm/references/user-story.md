# User Story

| Field | Holds |
| --- | --- |
| Story | As a named user role, what they want and why, in one sentence from their perspective, with no technical detail |
| Priority | Its rank among the objective's stories and why it ranks there, by the value it delivers |
| Independent test | How this story alone is demonstrated working end to end, as its user would exercise it, and the value that run proves |
| Rules | Each business rule the story must hold, one constraint per rule, each illustrated by concrete examples written as Given/When/Then, including negative and boundary cases |
| Out of scope | Behaviors and refinements excluded from this story, marking where more becomes overengineering, and any split into further stories |
| Traces to | The user's words this story formalizes, quoted verbatim, or the approval that set it |
